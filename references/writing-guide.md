## 叙事原则

### 核心思想

> "论文是一个简短、严谨、有证据支持的技术故事，带有读者关心的结论。" — 改编自 Neel Nanda

叙事原则建立在三大支柱之上，这三大支柱必须在引言结尾清晰表达：

**"是什么"**：1-3 个具体的新颖声明，围绕统一主题。模糊的声明如"我们研究了 X"会立即失败——评审需要精确、可验证的声明。

**"为什么"**：严谨的实验证据，令人信服地支持这些声明，包括诚实调优的强基线和区分竞争假设的实验，而不仅仅是展示"不错的结果"。

**"有何意义"**：为什么读者应该关心，将你的贡献与社区认可为重要的问题联系起来。

### 来自 Andrej Karpathy 的启示

> "论文不是你报告的一系列随机实验。论文推销的是之前不明显或不存在的一个东西。整篇论文都围绕这个核心贡献以外科手术的精度组织。"

这适用于你是否在呈现新算法、理论结果或对现有方法的改进理解。

**实际含义**：如果你不能用一句话陈述你的贡献，你就还没有一篇论文。其他一切——实验、文献综述、讨论——都只为了支持那个核心声明。

## 时间分配

大约**同等时间**投入：

1. 摘要
2. 引言
3. 图表
4. 其余所有内容

这不是夸张——大多数评审在到达方法部分之前就已形成初步判断。读者接触论文的顺序：**标题 → 摘要 → 引言 → 图表 → 可能看其余部分。**

### 评审阅读模式

- 摘要 100% 被阅读
- 引言被 90%+ 的评审浏览
- 图表通常在方法之前被检查
- 完整方法仅在建立兴趣后才被阅读

**含义**：前置论文的价值。不要埋没贡献。

## 摘要写作公式

### 5 句公式

1. **你做了什么**："本文提出/设计/构建了..."
2. **为什么这个问题重要且困难**
3. **你如何做**（包含专业关键词以便检索）
4. **你有什么证据**
5. **你最突出的数据/结果**

### 示例（好的摘要）

```
本文针对带随机需求的选址-路径问题（WSAA），提出一种改进的
Benders 分解算法。[做了什么]
传统 Benders 分解在处理大规模随机场景时收敛缓慢，
限制了其在实际物流规划中的应用。[为什么困难且重要]
本文引入懒约束生成、并行子问题求解和 Pareto 最优割平面
三种加速策略，显著提升算法收敛速度。[如何做，含关键词]
通过在多组标准测试集上的实验验证，[证据]
改进算法相比传统方法平均加速 3.2 倍，
最大实例规模达到 50 个候选设施、200 个客户点。[最突出结果]
```

### 应避免的开头

- "随着经济发展，物流行业..."
- "近年来，深度学习取得了显著进展..."
- "在大数据时代背景下..."

**以你的具体贡献开头。**

## 引言结构

### 要求

- **1-1.5 页**
- **模型/方法应在第 2-3 页开始**
- 必须包含 **2-4 条贡献列表**（每条 1-2 行）

### 结构模板

```markdown
1. 开篇引题（2-3 句）
   - 陈述论文解决的问题
   - 为什么现在很重要
2. 背景/挑战（1 段）
   - 为什么这个问题难？
   - 其他人尝试了什么？为什么不够？
3. 你的方法（1 段）
   - 你做了什么不同的事？
   - 实现贡献的关键洞察
4. 贡献列表（2-4 条）
   - 具体且可验证
   - 每条：1-2 行
5. 结果预览（2-3 句）
   - 最令人印象深刻的数字
   - 评估范围
6. 论文组织（可选，1-2 句）
   - "第二章介绍...第三章描述..."
```

### 贡献列表：好 vs 差

**好：**

- 提出改进的 Benders 分解算法，在大规模 WSAA 问题上平均加速 3.2 倍
- 引入三种加速策略（懒约束、并行求解、Pareto 割平面），显著改善收敛性
- 通过 50 设施、200 客户点的大规模算例验证算法有效性

**差：**

- 我们研究了 WSAA 问题（不是贡献）
- 我们进行了大量实验（太模糊）
- 我们对领域做出了若干贡献（什么都没说）

## 句子级清晰度

### Gopen & Swan 的 7 个读者期望原则

这些原则基于读者实际处理文字的方式。违反它们会迫使读者将认知精力花在结构上而非内容上。

#### 原则 1：主谓邻近

保持语法主语和谓语接近。任何 intervening 的内容读起来都是不太重要的打断。

弱："该模型，在经过大量数据训练和参数调优后，取得了良好效果"
强："该模型取得了良好效果，经过大量数据训练和参数调优"

#### 原则 2：强调位置（最后最重要）

读者自然强调**句末的词语**。将最重要信息放在那里。

弱："使用 Benders 分解后精度提升 15%"
强："使用 Benders 分解后，求解时间**缩短 15%**"

#### 原则 3：主题位置（先说背景）

句首建立视角。将"谁的故事"元素放在首位——读者期望句子关于首先出现的人或事物。

弱："一种新的割平面生成方法被提出"
强："针对收敛缓慢问题，本文提出一种新的割平面生成方法"

#### 原则 4：旧信息先于新信息

将熟悉信息（旧）放在主题位置用于向后链接；将新信息放在强调位置用于强调。

弱："稀疏割平面由 Magnanti 等人提出。标准 Benders 分解的二次复杂度促使了这项工作。"
强："标准 Benders 分解存在收敛缓慢问题。为此，Magnanti 等人提出了稀疏割平面方法。"

#### 原则 5：一个单位一个功能

每个话语单位（句子、段落、章节）应服务于单一功能。如果有两点，用两个单位。

#### 原则 6：动词表达动作

在动词中表达每个句子的动作，而非在名词化的名词中。

弱："我们对结果进行了分析"（名词化）
强："我们分析了结果"（动作在动词中）

#### 原则 7：背景先于新信息

在要求读者考虑任何新事物之前提供背景。这适用于所有层面——句子、段落、章节。

弱："公式 3 表明当学习率满足...时收敛有保证"
强："为保证收敛性，学习率须满足公式 3 的条件..."

#### 总结表

| 原则 | 规则 | 记忆法 |
|------|------|--------|
| 主谓邻近 | 主语和谓语保持接近 | "不要打断自己" |
| 强调位置 | 句末强调 | "最好的留最后" |
| 主题位置 | 句首背景 | "先说重要的" |
| 旧先于新 | 熟悉 → 陌生 | "在已知基础上构建" |
| 一个单位一个功能 | 每段一个观点 | "一个容器一个想法" |
| 动词表达动作 | 用动词，不用名词化 | "动词做事，名词坐着" |
| 背景先于新 | 先解释再呈现 | "先搭舞台" |

## 措辞与精确性

### 消除模糊

除非存在真正的不确定性，否则消除模糊：

- 删除"可能"和"可以"，除非必要
- "提供了*非常*紧的近似"流露出不安全感
- "提供了紧的近似"是自信的

### 避免空洞的强化词

- 删除：非常、极其、高度、显著（除非统计意义）
- 这些词暗示不安全感，而非强度

### 精确性优于简洁性

用具体术语替换模糊术语。

| 模糊 | 具体 |
|------|------|
| 性能提升 | 求解时间缩短 32% |
| 改善 | 准确率提高 X%，延迟降低 Y |
| 大规模 | 50 个候选设施、200 个客户点 |
| 快速 | 3 倍更快，50ms 延迟 |
| 效果良好 | Gap 在 50 次迭代内降至 1% 以下 |

### 术语一致性

用不同术语指代同一概念会造成混淆。**选择一个并坚持使用**：

- "模型" vs "网络" vs "架构"
- "求解" vs "训练" vs "优化"
- "算例" vs "场景" vs "实例"

### 词汇信号

**避免暗示增量工作的词汇**：

- 绝不："结合"、"修改"、"扩展"
- 使用："提出"、"设计"、"构建"、"引入"

**为什么**："我们结合了 X 和 Y"听起来像是把两个已有想法拼凑在一起。"我们提出一种利用 X 解决 Y 的方法"听起来是真正的贡献。

## 数学写作

### 通用原则

1. **在定理之前正式声明所有假设**
2. **在证明旁边提供直观解释**
3. **全文使用一致的符号**
4. **首次使用时定义符号**

### 符号约定

```latex
% 标量：小写斜体
$x$, $y$, $\alpha$, $\beta$
% 向量：小写粗体
$\mathbf{x}$, $\mathbf{v}$
% 矩阵：大写粗体
$\mathbf{W}$, $\mathbf{X}$
% 集合：大写花体
$\mathcal{X}$, $\mathcal{D}$
% 函数：命名函数用正体
$\mathrm{softmax}$, $\mathrm{ReLU}$
```

## 图表设计

### 设计原则

1. **核心图表至关重要**：通常是读者在摘要之后首先查看的内容
2. **自包含图注**：读者应无需正文即可理解图表
3. **图内无标题**：图注服务此功能
4. **矢量图形**：PDF/EPS 用于图表，PNG（600 DPI）仅用于照片

### 可访问性要求

8% 的男性有色觉缺陷。你的图表必须对他们有效。

**解决方案**：

- 使用色盲安全调色板：Okabe-Ito 或 Paul Tol
- 避免红绿组合
- 验证图表在灰度下有效
- 除颜色外使用不同线型（实线、虚线、点线）

## 常见错误避免

### 结构错误

| 错误 | 解决方案 |
|------|---------|
| 引言过长 | 将背景移至文献综述 |
| 方法埋没（第 3 页之后） | 前置贡献，精简引言 |
| 缺少贡献列表 | 添加 2-4 条具体、可验证的声明 |
| 实验无明确声明 | 说明每个实验验证什么 |

### 写作错误

| 错误 | 解决方案 |
|------|---------|
| 摘要空洞开头 | 以具体贡献开头 |
| 术语不一致 | 每个概念选择一个术语并坚持 |
| 被动语态过度使用 | 使用主动语态 |
| 处处模糊 | 除非真正不确定，否则自信表达 |

### 图表错误

| 错误 | 解决方案 |
|------|---------|
| 图表使用位图 | 使用矢量图（PDF/EPS） |
| 红绿配色方案 | 使用色盲安全调色板 |
| 图注需要正文才能理解 | 使图注自包含 |

### 引用错误

| 错误 | 解决方案 |
|------|---------|
| 逐篇罗列文献综述 | 按主题组织 |
| 遗漏相关引用 | 广泛引用相关文献 |
| AI 生成引用 | 始终通过搜索验证 |
| 引用格式不一致 | 使用 BibTeX 统一管理 |
